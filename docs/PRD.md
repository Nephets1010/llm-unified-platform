## 1. 产品目标与价值定位

### 1.1 问题陈述
- **接口碎片化**：每家大模型厂商 SDK/协议/鉴权各异，业务侧重复适配，技术栈被绑定。
- **权限失控**：API Key 散落各业务线，缺乏统一的租户、配额与审计，滥用与泄露风险高。
- **成本不可见**：Token 用量与费用无统一口径，无法按团队/项目分摊，预算超支常在账单后才暴露。
- **能力评估缺失**：模型选型靠主观印象，缺乏固定基准下的可复现横向对比。

### 1.2 解决方案与价值定位
构建**统一接入与能力评估中台**：分层网关 + 插件化适配。接入层统一 OpenAI 兼容协议 → 路由层按成本/延迟/健康度动态选路 → 适配层对接各厂商 SDK → 评估与监控层异步采集不阻塞主链路。

核心价值：
1. **一次接入，多模型可用**：业务侧只对接 OpenAI 兼容 API，厂商差异被适配层屏蔽。
2. **成本与权限可控**：租户/项目/Key 三级隔离，令牌桶硬限流 + 月度预算熔断，Token 级成本核算。
3. **可评估、可复现**：固定基准集 + 客观指标 + 报告对比，模型选型有据可依。
4. **生产级工程化**：CI/CD、可观测、灰度、容灾、审计，可直接作为团队级基础设施。

### 1.3 成功指标（量化口径）
| 指标 | 口径 / 目标 |
| --- | --- |
| 厂商接入数 | ≥ 4 个适配器端到端跑通（含自托管 vLLM/Ollama） |
| 网关开销 | P95 相对直连增量 ≤ 50ms，P99 ≤ 150ms |
| 吞吐 | 单机稳定承载 QPS ~100 |
| 调用可追溯 | 100% 调用可按 request_id 串起全链路；百万级 call_log 查询 P95 ≤ 3s |
| Token 计量 | 误差 ≤ 1%，千万级计量可扩展（分区 + 索引） |
| 成本分摊 | 租户/项目级账单准确率 ≥ 99% |
| 评测可复现 | 固定基准集重复跑分波动 ≤ 2%，报告可导出可对比 |
| 容灾 | 单厂商故障 30s 内自动 failover，熔断半开 30s 探测 |
| 交付节奏 | 阶段一端到端（认证→路由→多厂商→落库）可演示 |

## 2. 用户故事

### 2.1 平台管理员（Platform Admin）
1. As a **平台管理员**, I want **创建/管理租户并设置月度预算**, so that **我能按团队/项目核算成本并在超支前熔断**。
2. As a **平台管理员**, I want **生成/吊销 API Key 并设置粒度配额**, so that **我能精细化控制每个接入方的权限与用量**。
3. As a **平台管理员**, I want **在看板查看实时调用量/延迟/错误率/成本分布**, so that **我能及时发现异常与容量瓶颈**。
4. As a **平台管理员**, I want **配置路由策略（成本优先/延迟优先/加权轮询）与灰度规则**, so that **我能在 SLA 与成本之间取得平衡并安全发布**。

### 2.2 业务接入方（Business Consumer）
1. As a **业务接入方**, I want **用 OpenAI 兼容格式调用任意后端模型**, so that **我不需要为每个厂商编写适配代码**。
2. As a **业务接入方**, I want **流式（SSE）与非流式调用均稳定可用**, so that **对话类与批处理类场景都能接入**。
3. As a **业务接入方**, I want **拿到细粒度 Token 用量与成本明细**, so that **我能核算业务成本并做预算预警**。
4. As a **业务接入方**, I want **某厂商故障时自动切换备用模型**, so that **线上业务不因单点故障中断**。

### 2.3 评估工程师（Evaluation Engineer）
1. As a **评估工程师**, I want **用统一基准集批量跑多个模型**, so that **我能在同一基准下横向比较模型能力**。
2. As a **评估工程师**, I want **获得客观指标（准确率/召回/相似度/延迟/Token/成本）与评分报告**, so that **我能量化地做模型选型决策**。
3. As a **评估工程师**, I want **历次评测结果可对比、可复现**, so that **我能度量模型升级/降级带来的效果变化**。
4. As a **评估工程师**, I want **通过 MCP 工具网关接入外部工具并评测工具调用能力**, so that **我能评估模型在 Agent 场景下的真实表现**。

## 4. 模块职责与交互边界表

| 模块 | 核心职责 | 上游/依赖 | 下游/输出 | 交互边界（不做什么） |
| --- | --- | --- | --- | --- |
| **统一接入层** | OpenAI 兼容协议、请求/响应标准化、SSE 流式转发、request_id 生成 | 业务接入方 | 路由层、适配层 | 不做路由决策；不感知厂商差异；只做协议翻译与转发 |
| **能力评估引擎** | 评测集管理、批量推理、指标计算、报告生成 | 任务调度、适配层 | 报告存储、监控告警 | 不直接对外提供业务 API；评测流量走独立限流桶 |
| **任务调度** | 评测任务队列、并发控制、失败重试、任务状态机 | 评估引擎（触发）、配置管理 | 评估引擎、监控告警 | 不参与在线推理；只调度异步任务 |
| **监控告警** | 指标采集、Grafana 看板、告警规则、成本核算与账单 | 接入层/路由/评估 | 告警通知、账单明细 | 不阻塞主链路（异步采集）；不存储调用明细（明细在 call_log） |
| **权限与审计** | JWT/API Key 鉴权、租户/项目/Key 配额、操作审计 | 接入层、配置管理 | call_log、审计日志 | 鉴权失败立即拒绝；不参与模型路由；不读取 Prompt 内容（只记长度/hash） |
| **配置管理** | 模型池/路由/限流/灰度配置、热更新、版本与变更记录 | 管理台 / CLI | 各模块配置订阅 | 配置变更须有生效回执；禁止模块私自读文件绕过配置中心 |
| **日志与追踪** | 结构化日志、request_id 全链路透传、脱敏、链路聚合 | 全模块 | 日志/Trace 存储、Grafana | 不参与业务逻辑；不记录敏感明文；采样率可配 |

**关键交互边界约定**：
1. **接入层 ↔ 路由/适配层**：纯协议转换，无状态业务逻辑；适配层变更不影响接入层。
2. **评估引擎 ↔ 适配层**：复用同一适配层，但使用**独立限流桶**，避免评测抢占在线流量。
3. **监控 ↔ 各模块**：单向采集（pull/push），不得反向控制业务链路。
4. **权限与审计 ↔ 全模块**：横切关注点——前置鉴权 + 后置审计，所有对外调用必经。
5. **依赖方向**：接入层 → 路由 → 适配层；调度 → 评估 → 适配层；禁止循环依赖。

## 6. 非功能需求

### 6.1 性能
- QPS 设计 ~100（单机可平移）；网关 P95 开销 ≤ 50ms，P99 ≤ 150ms。
- 流式首 Token 延迟（网关侧）≤ 200ms（不含模型推理时间）；SSE 边收边发 + 预连接热池。
- 百万级 call_log 查询 P95 ≤ 3s；千万级 Token 计量可扩展（分区 + 索引）。
- 评测任务异步执行，**不阻塞在线主链路**。

### 6.2 可用性
- 网关可用性 ≥ 99.5%（单机部署下指"无单点崩溃、可快速恢复"）。
- 单厂商故障 30s 内自动 failover；熔断半开 30s 探测恢复。
- 配置热更新 5s 内生效，无需重启服务。
- Docker Compose 一键部署，可平移单机服务器；提供备份/恢复脚本。

### 6.3 安全（含密钥管理红线）
> **密钥管理红线（强制）**：任何密钥（API Key / 厂商 Key / JWT Secret / 数据库密码）**不得硬编码**在源码、配置文件、日志、镜像层、Git 历史中；必须通过**环境变量或 secret 挂载**注入；**gitleaks 等扫描零告警作为 PR 合并的硬性门槛**；`.env.example` 只放占位符不放真实值。

- API Key 仅存 hash（bcrypt/argon2），明文只在创建时一次性展示。
- 敏感字段（Prompt / Key / 邮箱 / 手机号）日志脱敏；审计日志留存 ≥ 90 天（可配置）。
- 鉴权失败立即拒绝（fail-closed）；租户/项目/Key 三级隔离，跨租户数据不可见。
- 输入校验与限流防滥用；生产部署强制 HTTPS；CORS 白名单可配。
- 最小权限原则：服务账号按需授权，禁止共享高权限凭据。

### 6.4 可维护
- **清晰模块边界**（见 §4）：单向依赖，禁止循环依赖；模块通过接口交互。
- 单元测试覆盖率 ≥ 70%（核心模块 ≥ 85%）；集成测试覆盖主链路（认证→路由→适配→落库）。
- 结构化日志 + request_id 全链路；错误码表文档化并随代码版本发布。
- Alembic 迁移可重复执行/回滚；CI 强制 lint / type-check / 测试通过。
- 配置版本化、变更可追溯；代码遵循 PEP 8 / ruff / mypy 规范。
- 技术选型基线（可扩展/高可用/易维护）：FastAPI + LiteLLM 思路、OpenAI 兼容层、vLLM/Ollama 自托管、加权轮询 + 成本优先路由、JWT + Redis 令牌桶、Prometheus + Grafana、RAGAS + 自建评测集、mcp-python-sdk。
